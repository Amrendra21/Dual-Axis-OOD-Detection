# Member 5: Dual-Axis OOD Evaluation Framework

This directory contains the standardized evaluation and benchmarking framework for the **Dual-Axis Out-of-Distribution (OOD) Detection on Molecular Graphs** research project.

The framework provides threshold-independent metrics, safety-critical operational thresholds, automated evaluation pipelines, publication-grade plotting utilities, and experimental tracking schemas designed to decouple and measure model performance across two orthogonal distributional shifts:
1. **Axis 1 (Structural / Syntactic Validity):** Chemical valency violations (e.g., hypervalent pentavalent "Texas" carbons).
2. **Axis 2 (Semantic / Scaffold Novelty):** Unseen Bemis-Murcko core scaffolds and external chemical domains.

## 2. Prediction CSV Format & Schema

The CLI evaluation runner [`evaluation/evaluate.py`](file:///c:/Users/Lenovo/Dual-Axis-OOD-Detection/evaluation/evaluate.py) reads tabular prediction CSV files generated by trained models.

### Column Requirements

Column names can be passed explicitly via CLI flags or automatically detected case-insensitively using candidate lists:

| Column Role | Auto-Detected Candidate Names | CLI Override Flag | Required? | Valid Values & Semantics |
|---|---|---|---|---|
| **Binary Label** | `label`, `y_true`, `true_label`, `target`, `is_ood` | `--label-col` | **Yes** | Exactly binary integers: `0` for In-Distribution (ID), `1` for Out-of-Distribution (OOD). |
| **OOD Score** | `ood_score`, `y_score`, `score`, `anomaly_score`, `pred_score` | `--score-col` | **Yes** | Continuous `float`. **Higher scores strictly mean more OOD-like / anomalous**. |
| **Benchmark** | `benchmark`, `axis`, `split`, `task`, `dataset` | `--benchmark-col` | Optional | Categorical string denoting the specific benchmark/split (e.g., `axis1_structural_validity`, `axis2_semantic_novelty`). |
| **Model Name** | `model_name`, `model`, `method`, `architecture` | `--model-col` | Optional | String identifier for model architecture / detection head (e.g., `GCN_Energy`). |
| **Random Seed** | `seed`, `random_seed` | `--seed-col` | Optional | Integer/string denoting experimental repetition seed (e.g., `42`). |
| **Sample ID** | `sample_id`, `id`, `smiles` | N/A | Optional | Identifier column for traceability; ignored during metric computation. |

### Strict Non-Fabrication & Multiple Benchmark Handling

- **Independent Benchmark Grouping:** When a benchmark column is present, the runner groups rows by `(model_name, seed, benchmark)` and computes metrics independently for each group.
- **Combined Dual-Axis Metric:** If and only if **both** Axis 1 (`axis1`, `structural`, or `corrupt` in name) and Axis 2 (`axis2`, `semantic`, or `scaffold` in name) are present for a given model and seed, a synthetic summary row named `combined_dual_axis` is generated containing the arithmetic mean and harmonic mean AUROC.
- **No Missing Data Imputation:** If a benchmark or model is omitted from the predictions file, `evaluate.py` **never** imputes, averages, or fabricates missing rows.
- **Zero-Tolerance for NaNs:** Any NaN or infinite values in evaluation columns trigger an immediate `ValueError` requiring data cleaning before execution.

## 3. Metric Definitions & Implementation

All metric functions are implemented in [`evaluation/metrics.py`](file:///c:/Users/Lenovo/Dual-Axis-OOD-Detection/evaluation/metrics.py):

### 1. AUROC (Area Under the Receiver Operating Characteristic Curve)
- **Interpretation:** The probability that a randomly chosen OOD sample receives a higher anomaly score than a randomly chosen ID sample. Range: $[0.0, 1.0]$ (random guessing = $0.5$, perfect = $1.0$).
- **Implementation:** Evaluated via `sklearn.metrics.roc_auc_score` if scikit-learn is present; otherwise falls back to exact Wilcoxon-Mann-Whitney U statistic calculation via `scipy.stats.mannwhitneyu`, or pure NumPy trapezoidal integration.

### 2. AUPR-Out ($\text{AUPR}_{\text{OOD}}$, `pos_label=1`)
- **Interpretation:** Area under the Precision-Recall curve treating **OOD as the positive class**. Measures anomaly retrieval efficacy under class imbalance.
- **Implementation:** Evaluated via `sklearn.metrics.average_precision_score` or pure NumPy weighted step integration ($\text{AP} = \sum_n (R_n - R_{n-1}) P_n$).

### 3. AUPR-In ($\text{AUPR}_{\text{ID}}$, `pos_label=0`)
- **Interpretation:** Area under the Precision-Recall curve treating **In-Distribution as the positive class**. Scores are negated ($-S$) so higher values represent in-distribution confidence.

### 4. FPR95 (False Positive Rate at 95% True Positive Rate)
- **Interpretation:** The fraction of in-distribution samples incorrectly flagged as OOD when the detection threshold is fixed such that at least 95% of true OOD samples are detected. Range: $[0.0, 1.0]$ (lower is better; perfect = $0.0$, worst = $1.0$).
- **Implementation:** The ROC curve ($(\text{FPR}_i, \text{TPR}_i)$ pairs) is computed with scores sorted in descending order. FPR95 is extracted as the false positive rate at the **first evaluated ROC threshold index where TPR reaches at least 95%**:
  ```python
  qualifying_indices = np.where(tpr >= target_tpr)[0]
  fpr_val = float(fpr[qualifying_indices[0]])
  ```

## 4. How to Run the Evaluation Framework

All commands below have been verified against the current CLI implementation.

> **Environment Note:** If running on a Windows system where system `python` defaults to a bare environment without scientific libraries, invoke using your Anaconda/virtualenv Python binary (e.g., `C:\Users\Lenovo\anaconda3\python.exe` or after `conda activate base`).

### 1. Generate an Example Predictions Template
Creates a 6-row sample CSV showing the required column structure:
```bash
python evaluation/evaluate.py --create-example-csv evaluation/example_predictions.csv
```

### 2. Evaluate Predictions
Run the CLI evaluation pipeline on a prediction CSV:
```bash
# Basic evaluation (saves summary to evaluation/results/evaluation_summary.csv by default)
python evaluation/evaluate.py --input evaluation/example_predictions.csv

# Custom output directory
python evaluation/evaluate.py --input evaluation/example_predictions.csv --output-dir evaluation/results

# Explicit column overrides (if custom header names are used)
python evaluation/evaluate.py \
    --input path/to/predictions.csv \
    --label-col true_label \
    --score-col ood_score \
    --benchmark-col benchmark \
    --model-col model_name \
    --seed-col seed \
    --output evaluation/results/my_model_summary.csv
```

### 3. Generate Visualizations
Plotting utilities in [`evaluation/plots.py`](file:///c:/Users/Lenovo/Dual-Axis-OOD-Detection/evaluation/plots.py) accept both summary tables and raw prediction files:
```bash
# Generate metric comparison bar chart from summary CSV
python evaluation/plots.py --summary evaluation/results/evaluation_summary.csv --output-dir evaluation/results/plots

# Generate multi-benchmark ROC curves from raw predictions CSV
python evaluation/plots.py --predictions evaluation/example_predictions.csv --output-dir evaluation/results/plots

# Generate both plots in one run
python evaluation/plots.py \
    --summary evaluation/results/evaluation_summary.csv \
    --predictions evaluation/example_predictions.csv \
    --output-dir evaluation/results/plots
```

## 6. Research Evaluation Protocol

To prevent methodological biases in molecular machine learning, the following protocol must be observed when reporting research findings:

### 1. Separate Reporting of Benchmark Comparisons
The project identifies four primary evaluation comparisons that address distinct chemical failure modes and must be reported separately:
- **ID vs. Corrupted (Axis 1 - Syntactic / Structural):** Compares `id_test_clean` against `id_test_corrupted_v3_graphs`. Evaluates whether a model detects physical valency violations (Texas carbons).
- **ID vs. Scaffold-Novel (Axis 2 - Semantic Novelty):** Compares `id_test_clean` against `ood_valid_clean`. Evaluates generalization across disjoint Bemis-Murcko scaffolds within Tox21.
- **ID vs. SIDER (Far-OOD Cross-Dataset Semantic Shift):** Compares `id_test_clean` against external pharmaceutical molecules from SIDER (adverse drug reaction dataset) to assess far-domain semantic shift.
- **Valid-Novel vs. Corrupted (Cross-Axis Interaction):** Compares `ood_valid_clean` against corrupted graphs to test whether structural valency detection remains effective on unfamiliar scaffolds.

### 2. Threshold Selection Protocol
- **No Threshold Tuning on Test Sets:** Any operational classification thresholds (e.g., threshold achieving 95% TPR) must be determined strictly using **validation partitions** (`id_val_clean` and validation corruption sets).
- Applying thresholds tuned on test sets to report operational accuracy constitutes data leakage and produces optimistic bias.
